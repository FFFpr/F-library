## 核心论点

1. 斯坦贝克写 T 型福特发动：火花汽油左右电池曲柄阻气门磁力发电机，还要吐痰念咒。今日扭钥匙踩油门。简化是设计师做了他们那部分；驾驶仍要课、考、数年才老练——使用者那部分。
2. 电脑常被骂为复杂之源，也可在后台用芯片把驾驶变简单更安全 = 复杂守恒：复杂度移到系统里。
3. 设计师原则：可理解。工具包括概念模型、语义符号、组织架构、自动化、模块化、手册与帮助。沟通过去、现在、未来（尼沃格特与魏德特：定位、模式、轨迹）。避免「这是错的」——自然界与游戏都没有错误信息；无反应时给协助。出错是教学时机。分而治之、模块化。
4. 请把「功能可见性」与语义符号分开：设计师关心可感知的信号。门上「推/拉」标签是失败后的社会性补丁。
5. 银器工作台看起来复杂，因每件工具可单学。伙伴关系：设计师给结构，用户给练习。

## 关键概念补全

**对现在/过去/未来的认知**：当前状态与可做操作；如何进来、能否撤销或复现；下一步预期（缺预期造成紧张）。

**语义符号 vs 功能可见性**：后者是吉布森的关系，存在与否不取决于是否被注意；设计师若「加上一个 affordance」多半只是让已有可能被看见 = 加语义符号。

## 一、T 型福特到现代车：伙伴关系

### 论证推理链

**论据 / 案例 / 事实**

- 开篇长引文与斯坦贝克自评：那时发动维护之难今日难想象；孩子摇篮里学内燃机，知识又突然不可信。现代两步，曾经要记忆、体力、脾气、希望与魔法。
- 最普通螺丝刀扳手锤子削皮刀铅笔都要练。系统处理复杂活动时，结果不会立即「谁都能用」。
- 现代车几百芯片后台混气、防滑、稳定、预警，可与他车沟通、按限速与交通推荐路线。驾驶者不必有意识操控这些。复杂度年年增，任务却更简单安全。

**推导**

「简单」发生在掌握规则之后的头脑里。只骂电脑不看嵌入式简化，是只看见界面层。

**结论**

驯服复杂 = 设计者组织沟通 + 使用者学习实践。

## 二、设计师原则：沟通过去现在未来

### 论证推理链

**论据 / 案例 / 事实**

- 设计曾等于外观评奖；现在含功能、需求、愉快体验。互动很大程度是沟通。
- 许多系统说不清当前状态。抹去历史则意外状态无法知如何进入、如何回去或如何再来。缺未来预期则任务难且紧张。
- 推打不开该拉的门：无错误信息，门只是不开，找对方法不难。电子系统不可见，无反应时人不知道下一步——此时要协助不是报错。最好不解自明。出错时解释问题并给工具，概念上变简单。积极建构的学习在「刚发现需要学」时最有效，太早教则厌。
- 图8.1：可抓把手=拉，平板=推且推哪里；开放楼梯可用，挡住下行的门是强制功能，防火灾逃进地下室。
- 术语被误用的历史与卷一第 1 章一致：设计界缺词就说「加了个示能」。作者强烈要求区分。缺适当语义符号就去找使用说明贴纸。

**推导**

责备应指向糊涂的系统。模块与分组提供可学结构（打平锤的工作台）。

**结论**

两前提：有针对性的交流 + 令人信服的概念模型。语义符号是自然舒适的沟通。

### 实操方法与设计原则

- 显示现在、保留过去（撤销/历史）、提示未来。
- 不要错误对话框；无反应时给可见原因与下一步。
- 模块化；手册与即时帮助当学习工具。
- 能靠语义符号就不要贴「推」「拉」。

## 段落总结序列

主旨：复杂既必要也可管理，条件是设计师把系统说清楚、使用者愿意学；沟通过去现在未来，用语义符号而不是错误信息和推拉标签。

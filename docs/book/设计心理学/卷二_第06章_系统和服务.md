# 卷二 第06章 系统和服务

## 本章位置

第五章要求机器与空间会交际。本章把对象换成**服务**：客户看见的前台只是俄罗斯套娃最外一层，每一层员工都有自己的前台与后台。产品与服务的界线常只是立场不同；要把全部体验当系统设计。第七章专攻服务里最折磨人的子系统——等待。

## 核心论点

1. 服务通常是复杂系统，连分公司遍布、部门众多的提供商也几乎不能理解，故难做良好运营模式，反馈特别困难。
2. 产品与服务常只是立场不同：每个产品都为用户提供服务（冰箱维护食品、相机提供回忆分享、ATM 对制造商是产品对客户是服务）。
3. **服务像俄罗斯套娃**：客户的后台是办事员的前台，办事员的后台是别人的前台。设计取决于立场，必须把客户、办事员、幕后助理、管理中心都考虑到。
4. 反馈与概念模型有两个最重要时期：第一次体验（学习做什么、该有什么预期）；出问题或意外延误时（信息、认证、操作链何处出错）。服务尤其跨组织时极难提供正确信息，比产品设计复杂得多。
5. 解决服务复杂性的唯一方法：当做系统，把全部体验作为整体设计。IDEO 拒绝只改列车内饰；苹果成功不在孤立 iPod，而在找、买、传、播与法律的整条系统。
6. 服务蓝图显示时间进程与互动深度；有表情的蓝图加上客户情绪。仍缺少员工情绪、更细后台、以及如何向人解释正在发生什么。不顺利时尤其需要反馈和概念模型。
7. 体验设计须同时重视职员与客户。纠正错误并承认错误的公司更受肯定。数据衡量容易压过不可测的人性；医院把患者变成数字，设备噪音可能有害。
8. 服务研究仍处初级阶段，投资远少于产品与制造；商业学校多做运营效率模型，缺针对被服务者与提供者的人性化设计原则。爱因斯坦：并非一切可计算，并非一切能计算的都有价值。

## 关键概念补全

**前台 / 台面上 vs 后台**：客户可见的人、地址、电话、网站 vs 视线外的操作（可能在另一栋楼、由国际网络、财团、政府完成）。

**俄罗斯套娃隐喻**：每个服务里嵌着另一个服务；每个后台对下一角色都是前台。

**交互设计**：随电脑电讯产品发展出的学科，从可用性扩到情感、体验与享受；嵌入式微处理器与通信芯片使它几乎成为所有设计的重要部分。

**设计思维 / 寻找问题根源**：永远不要只解决客户要求你解决的问题——客户常对症状反应；首要工作是发现真正要解决的潜在问题。

**服务蓝图**（琳恩·肖斯塔克，1980 年代初）：同时显示时间进程和互动深度。苏珊·斯普拉里根改为「有表情的服务蓝图」，捕获客户情绪。

**加工车间 vs 装配生产线**：前者按机器类型布置、每单不同、准备清理长、易错；后者按产品流程布置、重复、高效。许多服务（餐厅、医院）像加工车间；快餐像装配线。

## 一、俄罗斯套娃：产品、服务与循环的前后台

### 论证推理链

**论据 / 案例 / 事实**

- 作者工作多与计算机电讯及利用这些技术的初创公司有关，做电脑相机手机导航等交互设备：人的操作改变机器状态，再需要新操作，常须对话式设定参数。交互设计从理解可用性，加入情感，转向体验与享受。
- 服务界不如产品被深入研究。有人认为服务应追随优良交互设计主旨——伴随相关概念模型的良好反馈——事实上不那么简单。
- 定义：服务通常是有用的行动或为别人做的工作。冰箱：安全存储温度下维护食品 = 服务。相机：回忆和分享体验 = 服务。ATM：对制造商是产品，银行提供产品让客户用；对客户是方便办理基本银行交易的服务。
- 家用设施、电话、政府许可证护照所得税：庞大官僚规章制度，大批内部的人，很多部门声称负责非常规问题。个人只看见前端。后台神秘运作，造成顺利高效或困惑愚蠢。银行办事员是前台；幕后操作常不在银行完成。
- 误导：以为前台后台是一道简单分隔。一切事物有正面背面，每个后台成分也有自己的正面背面。对客户是后台的，对办事员是前台，对一个办事员是后台的对其他办事员是前台。
- 图6.1：柜台前客户与员工面对；(b)(c) 套娃。为现代系统服务作设计必须妥善处理循环性；设计内容取决于立场。
- 后台是操作层面，工作在此完成。失败或拙劣则产品/服务失败。复杂产品背后有复杂操作和技术、许多人使外部交互尽可能顺利。这些人都有自己的工具，各有内部外部成分。成功产品必须合并所有层面，协调支持所有可见和隐藏的服务和操作。产品存在于复杂交互网络中。
- 设计问题：如何让所有参与者——客户和员工——获得所需信息以理解业务操作？反馈与概念模型两个关键期：首次体验；问题或意外延误。产品上通常较易；服务跨多组织多地点很难。服务设计比产品设计复杂得多。

**推导**

交互设计的武器（模型+反馈）在服务上不够用，因为提供商自己都不理解整系统。套娃意味着「只优化柜台体验」会把混乱推向下一层员工。立场不写明，设计就会只服务看见你的那一层。

**结论**

必须把所有套娃层的前台都设计到：人人需要能理解业务操作的信息。服务比产品更依赖跨层反馈。

**启示**

画服务时不要只画客户旅程，给每个角色画他们看见的前台和看不见的后台。第一次使用与故障延误，是两场必测的「模型+反馈」考试。

### 实操方法与设计原则

- 产品当服务来定义：它为谁完成了什么工作。
- 循环：每层都有前后台；设计立场写全。
- 关键期：首次体验；出错/延误。

## 二、服务系统：阿西乐快线与 iPod

### 论证推理链

**论据 / 案例 / 事实**

- 许多服务既社会性又是复杂系统，庞大组织分布于完全不同地理位置，部分之间不理解或沟通差；跨组织更难。政府互动：复杂规章、复杂表格、办公室间无法逾越的延迟；即使人人乐于助人友好，联络困难仍令人沮丧。
- 唯一方法：当系统，全部体验整体设计。各部分孤立设计则不能很好配合。
- **阿西乐快线**：戴维·凯利，IDEO 三创始人之一。美国铁路公司要重新设计客车内饰以推东海岸华盛顿—波士顿高速线、吸引乘客。IDEO 说「不」——设计公司特点。设计思维：先确定真正问题。作者常说：永远不要解决客户要求你解决的问题，客户通常对症状反应，「寻找问题根源」常是最难部分。乘客和非乘客抱怨乘坐体验 ≠ 只改内饰。铁路公司同意彻底概念重构。合作伙伴奥本海默品牌顾问、斯迪尔凯思。十步骤：了解路线时间表价格计划 → 开始 → 进站 → 购票 → 等待 → 上车 → 乘车 → 抵达 → 继续这段旅程（火车站通常不是最终目标）。原要求只覆盖「乘车」一步。结果：网站、候车室、客车餐车内饰、车站信息亭、工作人员制服。多学科：人机工程、环境、工业设计、品牌。乘客数量增加，成全美最受欢迎铁路线之一。
- **便携音乐**：1970 年代盒式磁带；索尼 1979 随身听。微处理器、大内存、互联网商务、压缩 → 1990 年代电子播放器更小、可存成千上万首。障碍：①无明确合法途径取得音乐（买后复制到自己播放器合法，传播不合法）；②复制压缩传到播放器对普通人令人畏惧。
- 苹果进入后不仅支配数字播放器销售，也改变音乐公司对其产品的看法。人人以为秘诀是 2001 iPod 卓越设备设计。不。真正秘诀：不只产品，而是对寻找、购买、播放音乐及克服法律问题的整个系统简化。当时已有许多相当有吸引力且功能强大的数字播放器，但是孤立产品；多数音乐不能合法使用；人工把音乐弄进播放器太复杂。
- 系统阶段：获取音乐制造商许可（合法化）→ 浏览商店找到所需 → 购买 → 传入个人电脑 → 传入播放器 → 音乐库同步共享 → 听音乐 → DRM → 鼓励其他公司做附件（外置扬声器等）→ 控制零售环境 → 商标和许可证策划。
- 苹果以合理价格对每首歌合法授权谈判；网站+电脑应用浏览搜索试听充满趣味；购买轻松，下载到电脑毫不费力；iPod 连电脑时传输轻而易举；在电脑听或经联网电脑甚至家庭影音电视流式传输都容易。DRM 应音乐商要求防自由转移；苹果限制授权使售出音乐只能在苹果设备播 = 销售上的「锁定」：买得越多越锁在苹果上。问题持久，扩到电影视频书籍；媒体公司在研究少限制的保护，苹果也已放松。
- 后来鼓励附件（车载、秒表、录音、存储），苹果授权抽版税，无风险收入。包装盒也多花钱，视为迷人愉快体验的机会——用户体验从打开盒子开始。产品系列扩到手机电脑显示屏及照片视频电影游戏报刊书籍，物理结构和名称改过多次，基本理念经受住考验：无缝轻松。仍擅长三件事：建立紧密结合的系统而非孤立产品；系统优劣只取决于最薄弱环节；为全部体验作设计。
- 系统化思维是服务成功秘诀——迪斯尼主题公园、苹果、网飞、联邦快递或 UPS、亚马逊：设计整个系统，订单通过后台时不断告知每步进展，估算运输交货时间，允许改订单任何细节，从客户角度看控制得很好。幕后精密数学和计算机模拟保效率。枯燥运送通过适当提醒也可变积极体验。好的系统设计把全过程当以人为本、善于交际的系统。

**推导**

症状（抱怨车厢）不是根（十步里任何一步都能毁掉乘火车的决定）。iPod 硬件是系统里一步；合法、店、传输、DRM、附件、包装、零售任一步最弱，整个体验最弱。告知进度把后台变成交际。

**结论**

服务成功 = 系统设计：紧密结合、最弱环节决定优劣、为全部体验设计，并在过程中告知。

**启示**

接到「改一下界面/内饰」时，先列端到端步骤再决定改哪。做硬件先谈内容合法与传输，否则设备再漂亮也是孤立产品。物流也可以靠进度通信变体验。

### 实操方法与设计原则

- 拒绝只治症状；寻找问题根源。
- 列出全部阶段（阿西乐 10 步；iPod 许可到零售）。
- 三擅长：系统而非产品；最弱环节；全部体验。
- 过程中告知、可修改、时间估算。

## 三、服务蓝图；对体验进行设计

### 论证推理链

**论据 / 案例 / 事实**

- 服务中许多交互，客户与提供商都难理解。肖斯塔克提出服务蓝图。图6.2（斯普拉里根和陈，2009）：水平可见性线区分前台（台面上）与后台；垂直标注参与的组织部分+与客户有关部分；水平轴时间流阶段序列。
- 图6.3 有表情的服务蓝图：客户通过电脑应用呼叫服务台。图标周围「泡沫」= 挫折感程度，越大越强；注意最后被要求等待待机。客户在页面垂直位置 = 对服务满意：离可见性线越近越觉亲近。客户想法用文字表示。
- 蓝图是重要工具，但未掌握全部复杂性：还需员工情绪、更细后台、如何向客户或工作人员解释究竟发生了什么。也许可向双方展示简化蓝图：哪阶段已完成、目前在哪、还要哪些步骤。
- 顺利时提供良好体验不难。需求与机构复杂时易出错：信息不完整、关键人物缺席、等部件/授权。困难部分是意想不到的困难时也工作得很好。**除非能提供反馈和概念模型，否则无法提供出色的客户体验。**
- 丽嘉哲学（保罗·汉普 2002 引）：好酒店提出要求会被满足；极好的酒店甚至不需要提出要求。
- 服务往往是体验，须对职员幸福感舒适感给予与客户一样的重视。最有趣例子之一在一世纪前：有效服务设计秘诀基于对人的管理，而非技术。弗雷德·哈维在美国西部开连锁酒店，服务横贯大陆列车乘客。列车停靠补煤水，乘客舒展。哈维在停靠地开酒店，在允许的短暂停留内提供有效率服务。评估员工所花时间，也注意与客户互动细节。商业帝国约 75 年，芝加哥—旧金山间 65 家酒店，每年超 1500 万份食物。秘诀：严格注重细节和对职员培训。
- 丽嘉人力资源总监约翰·柯林斯：没人记得你从左还是从右服务，但一定记得是否真诚、是否真正喜欢为人服务、是否被强迫微笑。工作人员有权在客人需要时打破规则、提供额外项目、为意外需求作准备。订咖啡或酒：可能有其他人在房间？带上额外杯。汉普曾觉过度关注，直到自己送咖啡只带一杯却发现房里两人。
- 模范服务不能装：必须信仰。对职员需求与客户一样重视。很好对待、持续考察、互相帮助、能独立行动 → 为在那里工作自豪。受过移情训练、为客人提供愉快体验的职员，最终因工作成果相当愉悦。
- 商业系学生立即批判：这是有利可图的奢侈品市场，正常公司负担不起。作者不同意。
- 网站也是服务。重复访客可以非介入方式给建议。可能数百万人、需求与理解各异，须迎合每人又不能降低体验。真正考验是如何对批评作出反应，尤其行动激怒许多客户时——社交能力的真正考验：事情出错怎么办。
- 俱乐部会所酒店：商务会员（西北大学给作者访问权）。价格低、服务最低限度。大厅通常一人；信用卡插入机器收房卡自助入住退房，「即时入住/退房」当特色宣传。客房服务最低，但每房有附近可送餐餐馆清单；每层小厨房充足额外咖啡香皂洗发水日常用品免费。位于美国（和伦敦）主要商业城市中心，免费上网、不错书桌灯光电源——商务旅行者所需。自助省去大厅服务员。无浮华，繁忙商务人士通常无时间享受昂贵设施。展示关怀可以不需要多高成本。
- 总有添加新功能诱惑，代价是复杂性。网飞：杰出网站，每人一长串待看影片；同时固定数量在手、不限时；还一部寄下一部。个人档案：特别喜欢和不喜欢（看完评分）。因家庭室友共用，曾允许多个个人档案。后认为增加的复杂性超过价值，宣布停止：「动机完全是使服务尽量简单易用。太多成员发现难以理解，还须连续进出网站，十分烦琐。」许多客户反对，出现在网上讨论组。11 天后恢复：「简便只是一种优点，但它不会比实用更重要。」一客户：上周厌恶被一贯满意好感取代，因为这是足够尊重用户并听取需求的公司。
- 许多研究：出现错误后有效挽回很重要。有研究称适当纠正错误的公司可能比从不犯错的更受欢迎——有争议，最新精心管理的研究似乎不确定。所有研究都表明：承认并立即改正，比隐瞒或拒绝承认更容易受肯定。错误给公司机会证明关心、倾听、真诚纠正。服务关于体验；行动重要，真诚诚实对个体的关注也产生很大影响。

**推导**

蓝图把看不见的后台画成可讨论的模型，表情层把等待变成情绪数据。缺「如何对外解释」就仍不能交际。哈维/丽嘉把员工当体验的一部分来设计；俱乐部会所证明低成本也可对准真实需求（书桌电源、自助速度）。网飞删功能伤害了把多档案当体验核心的少数用户；撤回比「我们是为了你们简单」的单向宣布更像伙伴。

**结论**

出色体验 = 反馈+概念模型，尤其在意外时。员工与客户福祉一起设计。简便不比实用更重要；承认错误并改正本身是交际。

**启示**

蓝图拿给一线员工和客户看简化版：我在哪一步。授权员工为意外多带一只杯子。删功能前听把该功能当「必不可少」的人。出错后的 11 天窗口可以重建信任。

### 实操方法与设计原则

- 服务蓝图：时间 × 深度（可见性线）；可加情绪泡沫与亲近度。
- 向人展示简化蓝图当概念模型。
- 员工授权打破规则以满足意外需求；培训真诚而非强迫微笑。
- 低成本关怀：对准真实任务（商务：桌、灯、网、电源、快速进出）。
- 简便 < 实用；承认错误立即改。

## 四、华盛顿互惠银行；像工厂一样设计服务；医院

### 论证推理链

**论据 / 案例 / 事实**

- 华盛顿互惠银行：美国到处有分行，为办公室楼层格局和设计注册专利。图6.4 埃文斯顿离作者家不远的办公室：独立「柜台岛」，电线很好隐藏，无排队等待线，友好室内，专门儿童游乐区（图中上）。门卫迎接直接引导到岛上，代表帮助。职员与客户站一起共同查看交易，不像传统柜台屏障+职员隐蔽屏幕客户看不见。面对不可名状、隐藏秘密数据的官僚 → 合作友好交际的互动。
- 2009 经济危机倒闭，被摩根大通收购，宣布不再用该布局。互惠服务个人投资者，新颖非正式个性化有效，业务蓬勃。摩根大通主要商业客户大宗客户、向富人提供私人银行，需要私人保密讨论。回到传统布局：柜台和防弹玻璃隔离。对摩根大通业务需求可能适合，对普通客户放弃善于交际的设计令人遗憾。其他银行已开始引入类似设计。
- 同时为工作人员和客户考虑必要。愉快员工促成热情礼貌互动。作者与员工交谈：喜欢布局，展示每区域如何运作；让他从账户取 1 美元展示钱如何从机器自动安全处理——客户轻松，窃贼困难。积极展示每一细节，为工作地骄傲。拍照许可他们挤一起讨论（安全风险），也显示自豪。银行对员工和客户都好，从互动方式可看出。把老套行政管理式互动变成友好交际体验。
- 工厂：库存=缓冲区=等待处理的队列；商店库存=待购物品。瓶颈=细颈限制流量；工厂里某机器或工人跟不上，物资堆在后面成队列。收银员不够、出租车不够、高速不够大，都是瓶颈。消除常需更多资源，代价昂贵。运营管理学术做了大量减少瓶颈提高效率的工作。有的靠重新调整工作流、更有效流程；有的非常复杂。
- 传统服务设计旨在提高效率降低成本。医疗诊所候诊室从管理员看是满足需要的队列：已为医生设备付工资，候诊室满则设备核磁不再闲置、医护不必浪费时间等患者。患者希望满的是医生。急诊室时间宝贵，天平倾向患者。作者见过一急救室几乎是充满医务人员的候诊室：等新紧急情况时聊天、查邮件、个人事务——医生表示极不寻常。
- 加工车间：全定制，机器按类型（铣床一处锻压一处），每项工作流程不同，准备清理长，手工慢，案例特别，质量多变易错，一项经验难适用另一项。装配线：按流程放机器，冲压旁电焊旁螺栓，出错少质量高，问题根源可很快找出。餐厅基本像加工车间（菜单排列组合仍庞大）；快餐按装配线，食品测算规范，尽量自动化。医院属加工车间：建筑按程序类型组织，化验一部门、X 光扫描另一部门，病房按程序分隔，各医疗专业在建筑物不同部分，即使须当团队工作。患者前前后后穿梭。高准备成本、手工、较慢、频繁出错。
- 企业寻求赢利可理解。现代管理倾向数据衡量：「如果你无法衡量它，你就无法改进它」在科技管理中得到众多支持。强大工具，但不要让衡量影响力超过对重要问题的分析。并非一切重要的都可衡量；很多不重要的反而易衡量。需求经常超过对重要性的考虑。教育：易给学生测试总结数据，与生活成就关联微不足道，仍执著数据化评估。科学家测量能测的，宣布剩下的不重要。生活最重要部分是定性的。现代医学尤其医院：太多东西要衡量记录，没多少时间留给患者。

**医院观察**（国家科学院研究组，信息技术应用于健康护理，美国最好医院之一的儿科）：

- 早上 6:30 大规模会诊。到处有电脑。跟着医生护士巡诊、确诊、换班、药剂师填处方（大医院年填上百万，须避交叉反应误用），护士用条形码扫处方、药物、患者手环给药。
- 一大群：主治+5 驻院医生（从业前 3–5 年）+一二护士+研究团队。驻院各推电脑推车，多地叫 COW（computer on wheels）；一所医院改 WOW（workstation on wheels），因女患者听见门外说 the COW 误解称她为母牛。架子高适合站立打字，电脑电池在底部。5 台推车+护士大文件柜占很大空间。门口检查：扫屏幕「钙水平正常，蛋白偏低」——数字按实验室检查整理，非按症状诊断；不同医院实验室不同整理方式。专家能从数字整合患者状况。
- 复杂出现在交互界面：人—机、人—人、单位—单位。病床分配是专门服务，另有注意事项，又一个界面、又一个复杂来源。以为确诊或从急救/重症/产房/手术/康复出来就送任意空床——错误。
- 一医生实习时只被允许 15 分钟照看每名患者，却需长达 20 分钟填医学信息电脑系统。范德堡大学医学中心：护士只花 1/3 时间直接护理，剩下 2/3 的一半花在文档和药物治疗记录。
- 「患者在哪里」：作者进充满显示器输液泵监视器的房间，以为集中看所有患者。「就在你面前。」婴儿病房，设备太多看不见患者。现代医学：从医生角度看患者相当于一组测试结果和读数，作为人的身份差不多被遗忘。主治站门外听驻院审核测试、讨论建议，准备离开时敲门探头：「你今天感觉怎么样，福布斯先生？」这就是与患者的互动程度。
- 《新生儿协作网》：NICU 嘈杂（呼吸机、报警、对话走动），早产儿不能忽视正常背景噪音，高分贝造成情绪紧张，可能破坏大脑发育。即使转入「有益」的 NICU 仍须考虑整体噪声对健康。
- 图6.5：典型病房充满仪器，互不相干的读数和控制器，很多须手动记录，大量数字医疗记录掩盖患者作为人的身份。测试代价：注意力在测试不在患者；设备不同厂家不同交互方式引起错误（常归咎护士而非设计缺陷不协调）；噪音可能有害。医学水平越来越高，造成多大伤害？

**推导**

互惠银行把屏幕共享做成合作，专利说明他们把体验当战略；收购方客户结构不同，交际布局被「保密」需求替换——同一设计不是普适。工厂隐喻提醒：候诊室满是谁的效率？医院按专业分区是加工车间逻辑，患者成为在界面之间被传送的工件。可测的实验室数字赶走不可测的「福布斯先生」。COW 改名说明连暗语都会变成对患者的社会性伤害。

**结论**

服务设计必须同时为员工与客户。效率队列从哪一侧「满」取决于价值选择。医院界面与测量文化把人变成数字，伤害护理时间与环境。

**启示**

共享屏幕、站同一侧，可把官僚互动改成交际。换客户群前不要假设布局可直接迁移。测医院 IT 时把「文档分钟 vs 床边分钟」当核心指标。设备采购要协调交互方式与噪声，不要把错误默认算护士的。

### 实操方法与设计原则

- 去掉不必要的柜台屏障；共同看同一数据；儿童区等减少等待焦虑。
- 库存/瓶颈：写明队列是为谁缓冲（医生空闲 vs 患者时间）。
- 加工车间型服务接受高准备成本，不要假装自己是装配线。
- 衡量前先问：这数字与生活/护理成就有关吗？爱因斯坦：不是一切可计算，不是一切能计算的都有价值。

## 五、服务设计的现状

### 论证推理链

**论据 / 案例 / 事实**

- 日本民间谚语：日本人先用眼睛吃，然后才用嘴；饭的外观和味道同等重要。
- 对产品的整体体验远超出产品本身，与期望值有关：设置了什么期望、满足多少；预期方式、使用方式、对体验的反应；传达给拥有者和使用者的形象、公司形象、周边服务；最初广告、挑选购买、交付初始安装；连续使用以及与提供服务维护升级的公司的交互。从最初约定到实际体验到关系维护。
- 产品设计受关注；服务设计研究仍初级阶段，了解远少。产品有魅力：易办设计比赛，提交漂亮照片，评审几天——作者当过评审，想评所有方面不可能，作品太多时间太少（一个比赛上千件）。奖项主要反映外观和一小部分功能，有时产品根本不能使用，更不论市场成功。外观是活动核心，只有它决定奖项。
- 服务没有那种魅力，许多情况什么也看不见，必须在行动中分析。许多公司因服务质量成功或失败，但与产品比在服务研究上投资很少。世界范围问题。科隆国际设计学校：缺乏功能性、杂乱无章常见——无休止等待、不遵守约定、不友好、不可靠，从客户看日常服务如同忍受手续折磨；供应商抱怨客户过低价格预期、不可靠使用率、不积极雇员。
- 德国制造研发人均投资约是服务方面的 30 倍。问题世界范围。
- 缺乏标准原因：①管理者视服务为理所当然，不注重对服务和组织设计及员工培训；②痴迷数据的管理文化强调降成本、提高任何可测性能效率。服务面对人，可测的通常是持续时间和操作数量，不是客户或员工满意度。
- 服务重要性众所周知，《营销期刊》《运营管理杂志》《斯隆管理评论》《哈佛商业评论》频繁有研究。商业学校很少有人性化服务设计研究，大多集中运作效率、按预期客户数量优化费用的数学模型。结果：服务体验方面，既缺针对被服务者的设计原则，也缺针对服务提供者的。
- 服务复杂，但宗旨是帮助人，由人提供。现代化生产力追逐中忽视人类体验价值。测量关键参数很好，能专注薄弱环节和变化方向。不要忘记人为因素，减少复杂性，减少互动过程中的复杂程度。

**推导**

评奖机制选择了可见的外观，系统性地低估过程。制造/产品研发预算比服务高一个数量级（德国 30 倍），与「服务决定成败」的口头承认不一致。能测的时长与操作次数，替代了满意度。

**结论**

服务设计缺标准、缺投资、缺人性化原则。追求效率时不要忘记人。减少互动中的复杂程度。

**启示**

不要只用产品竞赛那套评服务。培训与组织设计不是「理所当然」。KPI 若只有时长和操作数，体验会被设计出去。

## 段落总结序列

主旨：服务是套娃式系统，必须整体设计前后台与全部旅程；蓝图、反馈和概念模型在出错时决定体验；效率测量不能把人变成数字。

最小标签集：陈述 / 必要依据 / 限定 / 例外 / 可替换例证 / 次要观点 / 续 / 过渡/场景

1. 【第一档·陈述】服务是复杂系统，提供商自己也难理解；产品/服务常只是立场不同。（本段是第2、3段的必要依据）
2. 【第一档·陈述】俄罗斯套娃：每层后台都是下一角色的前台；必须考虑所有立场。
3. 【第一档·陈述】反馈与概念模型关键在首次体验和出错延误；服务设计比产品难得多。
4. 【第一档·陈述】唯一解法是把全部体验当系统设计，孤立部分无法配合。
5. 【第二档·可替换例证】IDEO 拒只改车厢，列出乘火车十步并重做系统，乘客上升。
6. 【第二档·可替换例证】苹果秘诀是许可-店-传输-播放-DRM-附件-包装整条系统，不是孤立 iPod；系统取决于最弱环节。
7. 【第一档·陈述】服务蓝图显示时间与深度，表情蓝图显示情绪；仍缺员工情绪、细后台和对外解释。不顺利时尤其需要模型+反馈。
8. 【第二档·可替换例证】哈维/丽嘉靠培训与授权员工；俱乐部会所靠低成本对准商务真实需求；网飞承认错误恢复功能，简便不比实用重要。
9. 【第二档·可替换例证】互惠银行共享屏幕、无长队，员工与客户都自豪；换客户群后布局被弃。
10. 【第一档·限定】候诊室队列对谁有利取决于价值选择；医院像加工车间，复杂出在界面。
11. 【第一档·陈述】可测数字赶走患者作为人；设备噪音与文档时间伤害护理。不是一切可计算的都有价值。
12. 【第三档·过渡/场景】服务研究投资远少于产品，评奖偏外观；需要针对被服务者与提供者的人性化原则，并接到等待这一最可见的痛苦。

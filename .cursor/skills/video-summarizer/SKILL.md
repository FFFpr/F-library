# 视频深度总结与笔记生成指南 (Video Summarizer)

本 Skill 用于对用户提供的视频链接（B站、YouTube等）进行抓取、深度分析与结构化中文笔记整理。

---

## 工作流程规范

### 第一步：环境与访问校验（前置检查）

1. **模型校验**：
   - 检查当前调用的模型是否属于 **Gemini 系列**（例如 `gemini-3.7-flash`、`gemini-3.7-flash-high` 等）。
   - **如果当前模型不是 Gemini 系列，必须直接退出并告知用户**。

2. **链接访问校验**：
   - 尝试通过内置网络工具（如 `WebFetch` 等）访问用户提供的视频链接或获取视频详情/字幕/文稿。
   - **如果视频链接无法访问（如 404、失效、受限等无法解析内容），必须直接退出并向用户说明**。

---

### 第二步：视频内容深度分析与提炼

全面梳理视频的全部信息，并严格遵循以下要求进行整理：

1. **作者核心观点与推理链**：
   - 清晰罗列作者的核心论点与主张。
   - 梳理完整的论证推理链条：按照 `论据/事实/案例 -> 论证推导过程 -> 核心结论 -> 延伸推论/启示` 的结构逐层展开。

2. **实操与教学细节沉淀**：
   - 详尽记录所有涉及到的具体操作步骤、工具使用方法、配置参数、代码/配置实现、避坑指南等细节。
   - 包含用户提出的任何额外特殊要求（如有）。

3. **全信息捕获与题外话汇总**：
   - 对视频的总结应该包含所有信息，不得遗漏。
   - 即使是明显和视频主要内容无关的信息（如闲聊、题外插曲、个人经历等），也必须在总结中汇总为一句话：
     `除了视频主要内容外，作者还讨论了/提及了：1. ...，2. ...，3. ...`

---

### 第三步：文件存储与组织规范

所有总结文件统一存放在当前仓库的 `docs/video/`（相对仓库根目录；Cloud Agent 必须用这条）。若当前工作区不是本仓库，则写入 `C:\Data\F-library\docs\video\`。

1. **全中文语言要求**：
   - 所有文档内容、标题、目录名均使用中文。若英文原名有助于检索，可采用 `中文译名 (Original Name)` 的形式。

2. **按章节分布的单视频场景**:
   - 将视频总标题【翻译成中文】作为目录名。
   - 将每一章节的名称【翻译成中文】作为单个`.md`文件名。
   - 保存路径：`docs/video/[链接中文总标题]/[章节中文子标题].md`。

3. **单视频场景**：
   - 将视频原标题【翻译成中文】作为文件名。
   - 保存路径：`docs/video/[视频中文标题].md`。

4. **多视频 / 系列课场景（合集、分P、分章节讲解等）**：
   - 将链接总标题/课程总名【翻译成中文】作为目录名。
   - 将每一个分 P / 子章节的标题【翻译成中文】作为单个 `.md` 文件名。
   - 保存路径：`docs/video/[链接中文总标题]/[分P中文子标题].md`。

---

### 第四步：自引用与前置知识补全机制

每个生成的 markdown 文档必须具备**独立可读性（自闭环）**：

1. **前置概念补全**：
   - 如果视频中出现的核心前置知识点、专业术语或基础概念未被作者详细说明，在正文中必须先对该前提知识进行通俗且严谨的讲解补充。

2. **同系列交叉引用**：
   - 若该前置知识已在同一系列/合集中的其他视频中讲解过（本视频未重复展开），须在对应位置简要标注引用来源（如：`> 💡 相关前置概念详见：[分P文件名.md]`）。

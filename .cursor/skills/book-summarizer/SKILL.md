# 书籍深度总结与章节笔记生成指南 (Book Summarizer)

本 Skill 用于对用户提供的书籍链接、本地书籍文件或书籍文件路径进行解析、深度分析与分章节结构化中文笔记整理。适用于任意大模型。

---

## 工作流程规范

### 第一步：书籍来源校验与读取（前置检查）

支持三种输入来源（在线书籍链接、本地书籍文件、本地书籍文件地址），根据来源执行相应的处理与前置校验：

**硬性约束：禁止自己尝试其他来源。** 只处理用户本次给出的那一个来源。当用户给的来源无法获取时就停止：链接无法阅读全文 → 能否下载 → 都不行就停止。禁止用其他网站、搜索引擎、百科、盗版镜像、本机未提供路径的文件、或模型自身记忆/脑补来补全文、补章节或继续写笔记。

1. **在线书籍链接场景**：
   - **直接在线阅读**：首先尝试通过内置网络工具（如 `WebFetch` 等）直接读取网页或在线阅读器全文内容。
   - **下载尝试**：若无法直接在线完整读取全文（如仅展示摘要、内容分页限制或需解析下载链接等），则尝试下载书籍完整文件。
   - **失败停止**：若无法在线完整阅读且下载尝试失败（如链接失效、需鉴权付费、反爬拦截等），**必须立即停止处理并向用户明确说明失败原因**。

2. **本地书籍文件 / 文件地址场景**：
   - **文件存在性校验**：检查用户提供的本地文件或文件路径是否存在。
   - **失败停止**：若本地文件不存在或无法访问，**必须立即停止处理并告知用户文件不存在**。
   - **文件解析读取**：若文件存在，使用相应工具（如 `Read` 读取文本/Markdown/PDF 内容，或对应格式解析工具）完整读取书籍全文及目录章节结构。大体量 PDF（约 >40 MB）不要用 `Read` 打开二进制。
   - **扫描件 PDF**：先探测文字层（几乎无字且有图 → 扫描件）。确认后**先询问用户 OCR 语言（中文 / 英文）**，用户已指定则不必再问；**禁止猜测语言后开扫全书**。语言明确后再读取并遵循 `ocr-scanned-pdf`，抽成文本后才进入第二步。OCR 失败则停止：禁止换源、禁止用记忆补全文、禁止改原 PDF。在线下载得到的 PDF 若同样是扫描件，走同一路径。

3. **模型支持**：
   - 支持任意大模型，无需限制模型家族。

4. **本地解析工具**：
   - PDF / 扫描件 OCR：遵循 `ocr-scanned-pdf`，解释器优先仓库 `.venv`（`.venv/bin/python` 或 `.venv\Scripts\python.exe`）。
   - EPUB：用同一解释器 `import ebooklib`。
   - 缺依赖时跑 `.cursor/scripts/install-skill-tools.sh`（Windows：`install-skill-tools.ps1`），不要临时 `pip install`。

---

### 第二步：书籍内容深度分析与章节提炼

全面梳理书籍各章节的内容，严格遵循以下标准进行深度分析与总结：

1. **作者核心观点与论证推理链**：
   - 清晰罗列作者在各章节中的核心论点与核心主张。
   - 梳理完整的论证推理链条：按照 `论据/案例/事实 -> 论证推导过程 -> 核心结论 -> 延伸推论/现实启示` 的层级结构逐层展开。

2. **实操方法与教学细节沉淀**：
   - 详尽记录所有涉及的具体方法论、操作步骤、模型框架、工具参数、代码实现、避坑指南及案例剖析等细节。
   - 完整响应并包含用户提出的任何额外特殊要求（如有）。

3. **全信息捕获与题外话汇总**：
   - 对章节内容的总结必须全量捕获全部有效信息，不得遗漏重要事实与知识点。
   - 即使是明显与主旨弱相关的信息（如作者的题外插曲、闲聊、个人轶事等），也必须在章节末尾汇总为一句话：
     `除了本章主要内容外，作者还讨论了/提及了：1. ...，2. ...，3. ...`

4. **段落总结序列**
   - 在每个文件的最后，调用/segment-shortcut skill
   - 按照所调用skill指定的格式，将段落提炼内容列出

---

### 第三步：文件存储与目录组织规范

所有总结文件统一存放在当前仓库的 `docs/book/`（相对仓库根目录；Cloud Agent 必须用这条）。若当前工作区不是本仓库，则写入 `C:\Data\F-library\docs\book\`。

1. **全中文语言要求**：
   - 所有文档正文、章节标题、目录名均使用中文。若英文原名有助于检索或属于专有名词，可采用 `中文译名 (Original Name)` 的形式。

2. **目录与章节文件存储规范**：
   - **以书名为目录名**：将书籍原名【翻译/规范为中文】作为顶级目录名称。
   - **以章节名为 `.md` 文件名**：将每一章节的名称【翻译/规范为中文】作为单个 `.md` 文件名。
   - **前言/引言/附录**：独立的前言、绪论、结语或附录，亦分别作为独立的 `.md` 文件保存。
   - **保存路径结构**：
     `docs/book/[书籍中文名称]/[章节序号_章节中文名称].md`
     *(例如：`docs/book/深入理解计算机系统/第01章_计算机系统漫游.md`)*

3. **全书概览导读（可选/推荐）**：
   - 可在书籍目录下生成 `00_全书导读与架构.md`，汇总整本书的知识图谱、各章节逻辑关联与导航索引。

---

### 第四步：自引用与前置知识补全机制

每个生成的 markdown 章节文档必须具备**独立可读性（自闭环）**：

1. **前置概念补全**：
   - 如果章节中出现的核心前置知识点、专业术语或基础概念未在行文中详述，在正文对应位置必须先对该前提知识进行通俗且严谨的讲解补充。

2. **跨章节交叉引用**：
   - 若该前置知识已在本书其他章节中详细阐述，须在对应位置简要标注跨章节引用来源（如：`> 💡 相关前置概念与推导详见：[第02章_信息的表示和处理.md]`）。

---

### 第五步：同步书籍来源到输出目录（skill 执行的最后）

全部笔记写完、第四步补全之后，再把本次实际用到的来源落到 `docs/book/[书籍中文名称]/`。不要在写笔记过程中提前做。文件名用书籍中文名，去掉 Windows 非法字符 `\ / : * ? " < > |`。

- **本地 PDF**：将 PDF 复制到该目录（`[书籍中文名称].pdf`）。
- **在线阅读得到**：在该目录创建以书名命名的文本文件（`[书籍中文名称].txt`），正文写出所用在线链接。
- **经链接下载得到的文件**：将下载文件保存到该目录，并以书名重命名、保留原扩展名（如 `[书籍中文名称].epub`）。

若前面步骤失败停止（来源读不到、OCR 失败等），本步不做。
